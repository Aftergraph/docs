# ADR-005: Context Packs (aftergraph.context-pack.v0)

- Status: Accepted
- Date: 2026-09-07
- Scope: Aftergraph/docs (Knowledge Plane) portable context surface

## Context

V0.4 shipped a read-only Docs MCP; V0.5 added the full ISR claim registry
(C-001..C-008, registry-verbatim). Agents consuming the plane still had to
reassemble per-page provenance, dependency contracts, related claims and
reading order themselves — duplicating context engineering per client and
risking silent drift between what a page claims and what an agent carries.

ACC (context-continuity) defines portable actionable state transfer:
Sent != Received != Understood != Authorized != Completed != Verified. A docs
surface that only serves prose to agents inherits exactly that gap.

## Decision

Each rendered page ships a machine-readable **Context Pack** at
`/context/<page>.json`, schema `aftergraph.context-pack.v0`, generated by
`scripts/context-packs.mjs` (run at the end of every build, after the build
manifest — so packs carry the exact `site_commit`).

Pack invariants (enforced by validate gate #9):

1. **One pack per provenance page** — count must equal provenance.json pages.
2. **Provenance-bounded**: `source_repository@source_commit` (full 40-char
   SHA), `semantic_version`, `evidence_cut` copied from provenance.json.
3. **Freshness-bounded**: `site_commit` + `generated_at` + explicit
   constraints: the pack is never fresher than its build; the owning
   repository is authoritative over the rendering.
4. **Dependency-explicit**: `depends_on_contracts` derived from the contract
   graph; `related_claims` present on ISR-owned pages.
5. **Reading-path**: `next_reading` links, so a consuming agent can traverse
   the plane instead of guessing.

Canonical 5-state claim vocabulary (SUPPORTED / PARTIALLY_SUPPORTED /
CONTESTED / REFUTED / OBSOLETE) is a *projection* of the registry's verbatim
audit wording, never a replacement: `auditStatus` always travels alongside
`status`, and validate fails if the verbatim string is missing. REVERSED
live-replication findings project to CONTESTED — never silently upgraded.

## Consequences

- MCP consumers use `docs_get_context_pack` (V0.5 tool) for a
  provenance-complete bundle in one call.
- Packs are read-only derivations; owning repos remain the only sources of
  truth. No new registry, no graph DB, no CMS.
- Future ACC `ContinuityCapsule` interop lands here — only when ACC itself
  passes its own conformance gates. The pack schema is portal-local until
  then; it is explicitly NOT an industry standard.
